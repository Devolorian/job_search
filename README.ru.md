# job_search

[English](README.md) · Русский

Конвейер поиска работы на [Claude Code](https://claude.com/claude-code). Несколько раз в день он
собирает вакансии с карьерных страниц компаний, из публичного гостевого API LinkedIn, с досок
удалённой работы и из Telegram-каналов. Затем фильтрует их по вашему профилю и для каждой
подходящей вакансии создаёт папку, в которой лежат:

- ATS-совместимое резюме не длиннее двух страниц, собранное из **вашего собственного** банка фактов;
- сопроводительное письмо;
- ответ на вопрос «почему вы хотите к нам».

Каждую вакансию он заносит в трекер в Google Sheets (одна вкладка) и обновляет его по ответам
работодателей из вашего Gmail.

**Он ничего не выдумывает и ничего не отправляет сам.** Плановый прогон только готовит материалы.
Отклик уходит либо вашими руками, либо через `/apply`: он заполняет формы работодателя в вашем
браузере и ничего не отправляет, пока вы не подтвердите всю пачку. Каждая строка каждого резюме
восходит к `profile/cv/master_cv.yaml`, и это проверяет линтер.

## Быстрый старт

Нужно:
- [uv](https://docs.astral.sh/uv/);
- [Claude Code](https://claude.com/claude-code);
- Google Chrome или Chromium для рендера PDF (или задайте `CHROME_PATH`);
- macOS для встроенного планировщика. На Linux используйте cron.

```bash
git clone <этот репозиторий> ~/job_search && cd ~/job_search
claude                                  # затем внутри Claude Code:
/setup-profile                          # после того как положите резюме и PDF из LinkedIn в profile/inbox/
```

Без `profile/` всё работает на `profile.example/`, вымышленном продуктовом дизайнере из
Берлина. Так конвейер можно сначала попробовать:

```bash
uv run scripts/render_cv.py --generic -o /tmp/cv.pdf     # резюме из примера
uv run scripts/collect_himalayas.py --max-requests 2     # пробный запуск сборщика (ничего не пишет)
/job-scan --dry-run                                      # полный прогон без записи в Sheets
```

## Ваш профиль

Всё о вас лежит в `profile/`. Папка в `.gitignore` и никогда не покидает ваш компьютер.

| Файл | Что это |
|---|---|
| `inbox/` | ваше резюме (PDF/DOCX) и LinkedIn → More → Save to PDF; их читает `/setup-profile` |
| `cv/master_cv.yaml` | контакты, саммари, навыки, все пункты опыта, которые вы защитите на собеседовании |
| `search_profile.yaml` | роли и названия должностей, география, языки, скоринг, треки |
| `routing.yaml` | какие роли на каких источниках искать |
| `sources.yaml` | ключевые слова, Telegram-папка, id таблицы (накладывается на `config/sources.yaml`) |
| `excluded_companies.yaml` | компании, чьи новые вакансии не берутся (каждый отказ добавляется сам) |
| `CANDIDATE.md` | ваши правила и решения, а также язык, на котором отвечает Claude |
| `scan_rules.md` | ваши дополнительные фильтры: тип контракта, язык, порядок списка «Send today» |
| `cv/story_bank.yaml`, `cv/form_answers.yaml` | истории для собеседований; постоянные ответы на вопросы форм |
| `keyword_bank.yaml` | словарь вашей профессии, по желанию (по умолчанию — роли в данных) |
| `hooks/post_run.sh` | по желанию, запускается после каждого планового прогона |

`JOB_SEARCH_PROFILE=/путь/к/профилю` — профиль, лежащий в другом месте.

## Подключения

Секреты лежат в `~/.job_search/` (права 700), никогда не в репозитории.

- **Google Sheets (трекер).** Создайте сервисный аккаунт и сохраните его JSON-ключ вне
  репозитория. Пропишите `SERVICE_ACCOUNT_PATH=/путь/к/key.json` в `~/.job_search/sheets.env`.
  Создайте пустую таблицу «Job Search Tracker», откройте к ней доступ email-у сервисного аккаунта
  и запустите `uv run scripts/setup_sheets.py`. Он создаст вкладку трекера с формулой и запишет id
  в `profile/sources.yaml`.
- **Gmail (ответы работодателей).** Создайте OAuth-клиент типа Desktop app и сохраните его как
  `~/.job_search/gmail_client.json`. Затем один раз запустите
  `uv run scripts/collect_mail.py --auth`. Токен только `gmail.readonly`; токен с любым другим
  scope скрипт не примет.
- **Telegram (по желанию).** Получите API id и hash на my.telegram.org и строку сессии Telethon.
  Запишите их в `~/.job_search/telegram.env` как `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и
  `TELEGRAM_SESSION_STRING`. Сложите каналы с вакансиями в Telegram-папку и укажите её в
  `profile/sources.yaml` (`telegram.folder`, `enabled: true`). Для MCP-сервера задайте
  `TELEGRAM_MCP_DIR` с копией chigwell/telegram-mcp. Он работает только на чтение.
- **Чат вакансий (по желанию).** Ваш собственный бот присылает карточку каждой новой папки в
  личный чат с вами. Реакция на карточку отмечает отклик как отправленный. Задайте
  `TELEGRAM_BOT_TOKEN` в `~/.job_search/telegram_bot.env` и запустите
  `uv run scripts/tg_notify.py setup`.
- **wantapply (по желанию).** Запускается вручную командой `/wantapply` при подключённом
  браузерном расширении Claude.

## Запуск

**Прогон.** Все источники собираются один раз, затем на каждый трек запускается свой агент
(этапы описаны в разделе «Расписание»). Если компьютер включён не всегда, запускайте вручную:
сборщики дотягиваются до предыдущего сбора, так что дни простоя ничего не теряют.

```bash
scripts/daily_run.sh                     # полный прогон без интерфейса: сбор → треки → курсоры → чат вакансий
tail -f logs/$(date +%F).run.log         # следить за ним (у каждого трека ещё свой logs/<дата><суффикс>.run.log)
```

Или внутри Claude Code: `/job-scan` (все треки), `/job-scan --track <трек>`,
`/job-scan --dry-run` (без записи в Sheets).

**Отклики.** Только вручную, в сессии Claude Code с подключённым расширением Claude in Chrome.
Команда заполняет формы работодателей в вашем браузере, показывает одну таблицу на всю пачку и
ничего не отправляет до вашего «да»; каждый отправленный отклик сразу отмечается в трекере.
Никогда через LinkedIn Easy Apply, Telegram и другие личные сообщения или email; никогда не
создаёт аккаунт и не решает CAPTCHA. Если кнопка Apply в LinkedIn ведёт на сайт работодателя,
отклик оформляется там. Закрытая вакансия получает статус `closed`.

```bash
uv run scripts/apply_queue.py list       # что в очереди (apply.min_score, найдено за 21 день) и что отсеяно
/apply                                   # внутри Claude Code: заполнить → подтвердить пачку → отправить → отметить
/apply --min-score 80 --only vacancies/<папка>
uv run scripts/apply_queue.py mark --folder vacancies/<папка>   # отметить отклик, отправленный вручную
```

**Как следить за прогоном — мод `scan-status`.** Мод Claude Code держит рядом с чатом панель
«Прогон», которая обновляется каждые 5 секунд: состояние сборщика каждого источника (идёт /
готово / ошибка, сколько записей собрано), агент каждого трека и сколько он уже работает, папки,
созданные сегодня. Панель открывается сама, когда сессия стартует в этой папке; заново её
открывает `/scan-status`. Мод локальный (`~/.claude/dev-mods/…/scan-status/`) и в репозиторий не
входит; без него следите за логами через `tail -f`, как выше.

## Трекер

Одна вкладка Google Sheets, `applications` (`destinations.google_sheets.tab`). В неё пишут все
треки; вкладок с воронкой, статистикой или логами нет.

```
A Date added   B Applied on   C Company   D Role          E Source   F Link
G Match score  H ATS coverage I CV file   J Status        K First reply on
L Stage reached               M Notes (путь к папке)      N Days to reply (формула)
```

- Строка появляется, как только у папки есть готовое резюме, со статусом `Prepared`. На одну
  компанию — одна строка, навсегда.
- `Applied on` заполняется только при наличии подтверждения: вами, письмом-подтверждением от
  работодателя, реакцией на карточку в чате вакансий или командой `/apply` после отправки.
- Письма работодателей двигают `Stage reached` только вперёд (Applied < Assessment < Interview <
  Offer); отказ записывает `declined`. О приглашениях на собеседование и офферах бот ещё и пишет
  вам в Telegram.
- Статусы `skipped` (вы отказались сами) и `closed` (вакансия перестала принимать отклики)
  скрипты никогда не перезаписывают.
- Воронка считается по запросу: `uv run scripts/funnel_report.py` или `/funnel-review`.

## Расписание

```bash
scripts/install_schedule.sh 09:20 17:20      # LaunchAgent для macOS; --uninstall, чтобы убрать
```

Держите копию проекта вне `~/Documents`, `~/Desktop` и `~/Downloads`: launchd в эти папки не
заходит. Каждый прогон по порядку:

1. Собирает вакансии один раз.
2. Запускает параллельно по агенту Claude на трек по инструкции `prompts/daily_scan.md`.
3. Фиксирует курсоры Telegram.
4. Отправляет карточки в чат вакансий.
5. Только после утреннего прогона — разбирает логи дня (`prompts/log_review.md`).

Логи пишутся в `logs/`, папки вакансий — в `vacancies/`.

## Как принимаются решения

- **Фильтры по названию**: семейства ролей, исключения, проверка по описанию и маршрутизация по
  источникам.
- **География**: удалёнка по всему миру проходит. Удалёнка без единой названной страны тоже
  проходит; вакансия отсеивается, только если в ней прямо указан более узкий охват. Офис и
  гибрид проходят только в вашем городе или стране.
- **Язык**: вакансии на английском проходят. Остальные отсеиваются, если только ваш профиль не
  помечает язык для ручной проверки.
- **Скоринг**: веса в `search_profile.yaml`. Выше порога `viable` вакансия получает папку,
  резюме, письмо и строку в трекере; выше `strong` попадает в шорт-лист.

Подробности и причины — в `CLAUDE.md`. В docstring каждого сборщика записано, что было
измерено про его источник.

## Навыки (интерактивные)

| Навык | Что делает |
|---|---|
| `/setup-profile` | собирает `profile/` из ваших документов |
| `/job-scan` | запускает ежедневный прогон по требованию |
| `/apply` | заполняет формы откликов в браузере и отправляет после подтверждения пачки |
| `/scan-status` | открывает панель прогона (локальный мод `scan-status`) |
| `/interview-prep`, `/interview-debrief` | подготовка к собеседованию и запись того, что выяснилось |
| `/follow-up` | черновики напоминаний по откликам без ответа; отправляете вы |
| `/funnel-review` | показывает, что конвертируется, и предлагает изменения конфига |
| `/form-answers` | черновики ответов на дополнительные вопросы формы отклика |
| `/humanize-cv`, `deslop` | убирает следы сгенерированного текста, только фактами из банка |
